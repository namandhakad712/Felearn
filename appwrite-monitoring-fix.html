Appwrite Monitoring System Fix

Problem: Your application was crashing due to Appwrite database errors, specifically:
  • Missing collections (404 Not Found)
  • Rate limiting issues (429 Too Many Requests)

Changes Made

The following changes have been made to fix the issues:

1. Error Handling Improvements

  • Added proper error handling for missing collections
  • Added rate limiting protection with exponential backoff
  • Made initialization non-blocking so your app continues even if monitoring fails

2. Rate Limiting Protection

  • Added client-side rate limiting for error tracking (max 10 errors per minute)
  • Added debouncing for error events (1 second between errors)
  • Added local storage for errors when rate limited

3. Configuration Changes

  • Disabled non-essential monitoring features
  • Reduced sampling rates to minimize API calls
  • Increased collection intervals to reduce API call frequency

How to Fix Appwrite Database Issues

To completely fix the issues, you need to create the missing collections in your Appwrite database:

Option 1: Use the Setup Script

Run the provided setup script to create all required collections:

npm install node-appwrite
set APPWRITE_API_KEY=your_api_key_here
node setup-appwrite-collections.js

Option 2: Manually Create Collections

Create these collections in your Appwrite console:

  • alert_configs
  • system_metrics
  • alerts
  • performance_logs
  • error_logs
  • request_logs
  • api_usage_logs

Required Attributes for alert_configs

  • name (string, required)
  • metric (string, required)
  • threshold (float, required)
  • operator (string, required)
  • enabled (boolean, required)
  • recipients (string array, optional)

Re-enabling Features

After creating the collections, you can gradually re-enable monitoring features in src/config/monitoring.ts:

// Feature flags
features: {
  realTimeMonitoring: true,  // Re-enable when collections are created
  performanceTracking: true, // Re-enable when collections are created
  errorTracking: true,       
  userAnalytics: true,       // Re-enable when collections are created
  alerting: true,            // Re-enable when collections are created
  healthChecks: true,        // Re-enable when collections are created
},
Success: Your application should now run without crashing, even with the missing collections. For full functionality, create the required collections in Appwrite.
